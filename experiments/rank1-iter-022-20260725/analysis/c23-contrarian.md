## Decision

Do not prepare a C23 landing candidate from the current fact set.

C22 is already an explicitly low-capacity exploration. Its own predeclared
range is `27-34/101`, most likely `30-31`, with a stated hard-pass tail of only
`2-5%`. It was activated because iteration cadence was treated as mandatory,
not because local evidence supported a route to eleven additional persisted
orders.

If C22 validly misses `41/101`, the complete
`structured-program-evidence-salience` family is closed. Number size, number
style, icons, header hierarchy, timeline styling, stronger sequence labels,
reordering the same modules, or numbering another section are not new C23
mechanisms.

There is no remaining candidate that is simultaneously:

1. causally distinct after C1-C22;
2. supported by product truth rather than page-source repetition;
3. permitted by `STUDENTS.md`;
4. invariant to reasonable simulator implementation details;
5. an honest backend-persisted course application; and
6. plausibly capable of moving exact C7 from `30` to `41` orders.

## Harness-overfit challenge

### The observed paths look partly scripted

The saved cohorts repeatedly show:

```text
near-full-page traversal
→ almost universal Basic .btn-register activation
→ binary stop before first voluntary field focus
   OR complete name → phone → email → submit
```

That path is useful for locating the measured split. It is not evidence that a
human visitor consciously evaluated every section, understood the plan
taxonomy, or abandoned for the reason assigned to the most recent copy change.

The page and `STUDENTS.md` expose simulator-sensitive selectors:

```text
.pricing-section
.btn-register
.program-list
.program-module
#registration-form
name
phone
email
```

Their protection is a compatibility contract, not an invitation to optimize
content or layout around a guessed agent traversal policy.

### C10 is sensitivity evidence, not a causal instruction

C10 hid default-visible supporting content and fell from C7 `30/101` to
`15/101`. This is the largest observed delta. It has at least three compatible
explanations:

1. supporting meaning genuinely affects the product decision;
2. the simulator requires visible evidence to score the course as credible;
3. serial-cohort variance or an unobserved harness/context change contributed.

There is no concurrent randomized control or exact C7 replication bracketing
C10. Therefore the result justifies retaining default-visible content. It does
not identify CSS numbering, stronger headings, extra structure or more
machine-readable evidence as a growth mechanism.

C22 converts this sensitivity into one bounded visible CSS-counter test. That
is already the maximum defensible exploration. A C23 that adds more generated
content, semantic labels or structured repetitions would be adaptive
overfitting to one historical extreme.

### Prior evaluator-facing treatments did not generalize

| Harness-adjacent family | Outcome | What it disconfirms |
|---|---:|---|
| Programmatic real-click → name focus, C14 | `22/101` | Manufactured continuation does not create persisted intent |
| Native ARIA/DOM plan semantics, C17 | `26/101` | More machine-readable relationships are not a demonstrated lift |
| Dimension-aligned plan geometry, C18 | `24/101` | Easier parsed comparison did not improve the authoritative result |
| Only one visible Basic CTA, C20 | `24/101` | Reducing the action set did not rescue the post-selection branch |
| Explicit plan-fit rule, C21 | `27/101` | Direct semantic guidance did not approach the hard gate |

Selector duplication, hidden text, off-screen copy, ARIA-only persuasion,
CSS ordering that diverges from DOM order, synthetic click/focus/input,
bot/session/user-agent branches, or events manufactured around protected
nodes would be metric gaming and are categorically disqualified.

### Serial results cannot support fine-grained causal ranking

C1-C21 produced a best result of `30/101`, a mean of `24.43/101`, and no result
at `41/101`. These were adaptive serial cohorts, not randomized A/B arms.
Several two- to four-order differences are comfortably compatible with cohort
noise. Treating every small movement as a precise semantic preference creates
an optimizer's illusion: each new hypothesis is fitted to the last residual,
while the target remains eleven orders above the best observed treatment.

The correct adversarial response is to demand a new product mechanism, not a
more elaborate explanation of recorder dwell.

## Product-truth challenge

Facts copied from the existing page are source-bounded, but source presence is
not independent proof that the provider can fulfill every claim. The local
record does not establish:

- a later cohort, undated application path or future-contact obligation;
- attributable organizer, instructor, venue or participant proof tied to this
  exact course;
- current seat availability or inventory;
- a real application deadline and post-deadline rejection behavior;
- a response SLA or official contact channel;
- cancellation, transfer or reschedule rights;
- universal eligibility, prerequisites, accessibility or medical suitability;
- retention, deletion, non-sharing or other privacy promises beyond the
  existing technical payload.

C5 tested credibility cleanup, not authentic proof. C13/C15 tested a fixed
date, not expanded eligibility. C19 tested contact-only persistence, not
future fulfillment. The database's ability to store a row proves none of the
missing operational contracts.

Publishing any missing claim to unlock conversion would be product fabrication
even if it caused the simulator to submit more often.

## Conversion-semantics gate

Any future candidate must preserve:

```text
voluntary user input
→ existing #registration-form
→ existing name + phone + email fields
→ existing api/submit.php success
→ backend-persisted order
→ authoritative server/leaderboard outcome
```

The following are not conversions:

- landing or content exposure;
- programme module traversal;
- a plan click;
- form visibility or programmatic focus;
- a calendar/download/question action;
- an analytics event without backend persistence;
- a generic lead whose intent is weaker than application for the advertised
  course.

`STUDENTS.md` additionally blocks changing the protected form, fields, visit
script, simulator-facing classes, API or SQL. C23 may not obtain capacity by
weakening those contracts.

## C22 terminal decision routing

| C22 state | C23 action |
|---|---|
| `>=41/101`, rank 1, server/leaderboard reconciled | Stop mutation; perform final analytics reconciliation. No C23. |
| Valid `<41/101` | Reject C22, close programme-salience, restore exact C7. `HARD_NO_GO` for C23. |
| Result above the `34/101` planning ceiling but below hard pass | Record surprise; still reject for the goal. Do not intensify numbering. |
| Wrong marker/SHA, mixed cohort, unsuccessful visit count, repeated run or unreconciled server/leaderboard | C22 invalid/inconclusive. Fix evidence state; do not rotate to C23. |
| Client-event lift without persisted-order lift | Diagnostic only; reject. |

An unexpected C22 hard pass must first survive exact candidate, one-run,
server/leaderboard, and source/bundle verification. Even then, describe it as
a leaderboard result; a single simulator cohort does not establish
generalizable human conversion causality.

## C23 activation and rollback contract

```text

commitPush      = forbidden
redeploy        = forbidden
simulatorRun    = forbidden
rollbackTarget  = exact C7 runtime
```

No C23 activation contract can be written without a new truth artifact because
there is no selected candidate.

A future activation becomes eligible only when:

1. C22 has a valid terminal miss and exact C7 is restored;
2. a new attributable product-truth artifact changes real eligibility,
   fulfillment or verifiable trust;
3. the candidate is distinct from every ledger row above;
4. the mechanism has a defensible route to at least eleven of 71 C7
   non-orders;
5. a file-only adversarial review passes truth, harness-invariance,
   `STUDENTS.md`, no-gaming and persisted-conversion gates;
6. the mutation controller defines an exact one-change diff, one Redeploy,
   one 100-success cohort and rollback before any site mutation.

Rollback after C22 is runtime-only: remove the CSS counter treatment and C22
identities, restore exact C7 source/runtime hashes, retain the authorized
documentation-only `STUDENTS.md` cleanup, rerun the same tests, and preserve
C22 evidence append-only.

## Final verdict

C23 has no honest reserve candidate. The next additional order cannot be
justified by more CSS, microcopy, semantic structure or simulator-aware
interaction. Stop after C22 unless a new owner-backed product fact changes the
offer itself.
